# upstream-hooks.txt - the upstream files that the MSIL fork changes, and the tests that cover
# each change (plan M11, item 7; section 12 row 'Upstream merges ... also maintain
# msil/utils/upstream-hooks.txt').
#
# Part of the LLVM Project, under the Apache License v2.0 with LLVM Exceptions.
# See https://llvm.org/LICENSE.txt for license information.
# SPDX-License-Identifier: Apache-2.0 WITH LLVM-exception
#
# Checked by msil/utils/ci/check-upstream-hooks.py and run by msil/utils/ci/upstream-hooks.ps1
# (the 'upstream-hooks' step of msil/utils/run-m1-gate.ps1, the upstream-merge gate and the
# Windows CI job). An upstream merge, or a milestone that changes another upstream file, updates
# this file in the same commit.
#
# Format. One entry per line; a line whose first non-blank character is '#' is a comment, and
# blank lines are ignored. Paths are relative to the repository root, with '/'.
#
#   hook <path>               an upstream file that the fork changes. The indented lines below
#                             it (at least one of lit, gtest, compile, utc, none) say how its
#                             upstream behaviour is tested:
#     lit <path-or-glob>      upstream lit tests ('*', '?' and '[...]' globs over test files;
#                             each must match at least one file). A lit line may also name a
#                             fork test when it is the only runnable check of a hook
#                             (lld/test/MSIL/dispatch.test for lld/test/lit.cfg.py's feature
#                             map): the lit leg then runs it and requires it to PASS, whereas a
#                             fork line only has to exist. All lit lines together are the
#                             lit inputs that 'check-upstream-hooks.py --list-lit' prints and the
#                             lit leg runs in one llvm-lit invocation with the shared build's
#                             tools. The list goes to lit through a response file
#                             (<build>/lit-results/upstream-hooks.rsp, '@<file>' inside -LitArgs),
#                             so its length never meets the Windows command-line limit.
#     gtest <exe> [<filter>]  a gtest binary of the build (path relative to the build directory)
#                             whose tests exercise the change; the gtest leg runs every test of
#                             TargetParserTests, MCTests and LLDAsLibAllTests except the host- and
#                             target-gated ones that upstream-hooks.ps1 excludes by name (<filter>
#                             only documents the relevant tests). Only those three binaries
#                             (GTEST_BINARIES of check-upstream-hooks.py, which the manifest leg
#                             compares with the binaries of the gtest leg) are valid
#     compile                 compiled by the compile leg in the private hooks build tree with
#                             -Werror=switch. Valid only on the leg's translation units
#                             (llvm/lib/Target/ARM/AsmParser/ARMAsmParser.cpp and
#                             lldb/source/Plugins/Process/gdb-remote/GDBRemoteCommunicationClient.cpp;
#                             COMPILE_FILES of check-upstream-hooks.py, which upstream-hooks.ps1
#                             reads with --list-compile) and on a file that one of them #includes
#                             directly (the include path, such as "llvm/MC/MCContext.h", is a
#                             suffix of the hook's path). Each of the two needs a hook block with
#                             a compile line
#     utc <test>...           update_llc_test_checks tests (llvm/test/tools/UpdateTestChecks/
#                             update_llc_test_checks/<test>.test) that the 'utc' leg of
#                             msil/utils/ci/lit-legs.ps1 and lit-legs.sh runs through
#                             msil/utils/run-utc-tests.py. Each must exist and be one of the
#                             leg's tests: the list stays in the leg scripts ('$utcTests = @(...)'
#                             of lit-legs.ps1, 'utc_tests=(...)' of lit-legs.sh), and the manifest
#                             leg checks that both lists parse, that they are equal and that every
#                             utc name is on them
#     none <reason>           no runnable upstream test; the reason is required
#     fork <path>             a fork test that pins the MSIL side of the change (must exist)
#   fork-only <path>          a fork file inside an upstream directory (not a hook). The path
#                             must not exist in the upstream base: a file of the base that the
#                             fork changes needs a hook block, and the check fails a fork-only
#                             line for it
#   switch-default <path>     a file with an exhaustive object-format switch (see below) whose
#                             XCOFF case needs no MSIL case because that switch has 'default:'.
#                             Per switch: an XCOFF case of the file in a switch without its own
#                             'default:' (one in a nested switch does not count) still needs an
#                             MSIL case. Stale when 'git grep' finds no XCOFF case label in the
#                             file
#   switch-other <path> <reason>
#                             a file whose unqualified 'case XCOFF:' or 'case IsXCOFF:' belongs
#                             to another enumeration. Only those labels are exempt: a qualified
#                             'case Triple::XCOFF:' or 'case MCContext::IsXCOFF:' of the file is
#                             checked as in any other file. Stale when the file has no
#                             unqualified XCOFF case label in code
#   allow <test> <reason>     one lit input whose FAIL the lit leg accepts: only an environment
#                             failure of that one test file (a tool or runtime the build cannot
#                             provide), and the reason names it. Never a glob, a directory or a
#                             real mismatch; an entry whose test passes is stale and fails the
#                             check. A real failure is fixed in the fork, or the test is dropped
#                             from its lit line with a comment.
#   min-pass <N>              the lit leg needs at least N PASS results (XFAIL does not count)
#
# The manifest leg (check-upstream-hooks.py --check) compares this file with the repository:
#   - The upstream base is $MSIL_UPSTREAM_BASE if set; else MERGE_HEAD while a merge is in
#     progress (the upstream commit being merged: the merge gate checks the uncommitted merge,
#     and the diff against MERGE_HEAD is the fork's footprint on the new upstream); else the
#     second parent of the last first-parent merge whose subject starts '[MSIL] Merge upstream
#     llvm-project main at ' (merge commits keep that subject). No base (a shallow clone, for
#     example) is an error, never a pass.
#   - The changed paths are 'git diff --name-only <base>' (the working tree, so uncommitted work
#     counts) plus the untracked files. Every changed path outside the fork-only prefixes
#     (FORK_PREFIXES of check-upstream-hooks.py: llvm/lib/Target/MSIL/ llvm/test/CodeGen/MSIL/
#     llvm/docs/MSIL/ llvm/unittests/Target/MSIL/ clang/test/CodeGen/MSIL/ msil/ .github/msil/,
#     and from M13 lld/MSIL/ lld/test/MSIL/ llvm/include/llvm/CLI/ llvm/lib/CLI/
#     llvm/unittests/CLI/ llvm/tools/llvm-cil-dump/ llvm/test/tools/llvm-cil-dump/
#     llvm/tools/llvm-cil-copy/ llvm/test/tools/llvm-cil-copy/ llvm/test/MC/MSIL/) that is not a
#     fork-only line needs a hook block; a hook block or fork-only line for an unchanged path is
#     stale, and a fork-only line for a path that the base has ('git cat-file -e
#     <base>:<path>' succeeds) fails.
#   - Every exhaustive object-format switch of the whole monorepo (built or not: lld, bolt,
#     lldb, other targets) has an MSIL case. Such a switch has a 'case Triple::XCOFF:' or
#     'case MCContext::IsXCOFF:' label (with or without 'llvm::') or an unqualified
#     'case XCOFF:' or 'case IsXCOFF:' (class scope or 'using enum') in a C, C++ or
#     Objective-C source file. Every such label in code (comments and string literals do not
#     count) needs an MSIL case label ('case Triple::MSIL:', 'case MCContext::IsMSIL:',
#     'case MSIL:' or 'case IsMSIL:', with or without 'llvm::') in the same switch: the
#     innermost 'switch (...) {' body around it, not a switch nested in it. Triple::MSIL
#     elsewhere in the file (a comparison, a comment, a case of another switch) does not cover
#     it. The exemptions are per switch: in a switch-default file a 'default:' label of the
#     same switch also covers the label; a switch-other file exempts only its unqualified
#     labels. Where the braces of a file do not match (preprocessor conditionals), or a label
#     is outside every switch body (a macro), the check counts instead (the conservative
#     fallback): at least as many covering labels (MSIL case labels, and in a switch-default
#     file also 'default:' labels) as XCOFF labels that need cover. A problem names the file
#     and the line of the uncovered XCOFF case.
