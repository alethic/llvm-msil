# msil/: the MSIL project

Everything of the MSIL backend fork that is not part of LLVM or clang proper: the execution
test suite, its harness and verification tools, the CI and gate scripts, and the build helpers
of the development host. Like LLVM, the project ships compiler tools only; nothing here is a
runtime library that compiled programs need (generated assemblies depend only on the .NET base
class library and the native libraries they P/Invoke). It is built as an LLVM *external
project*, so no upstream CMake file changes:

```sh
# CI and other hosts: the cache file sets projects, targets and the external project.
cmake -G Ninja -S llvm -B build -C msil/cmake/caches/MSIL.cmake
# or, explicitly:
cmake -G Ninja -S llvm -B build -DLLVM_EXTERNAL_PROJECTS=msil -DLLVM_EXTERNAL_MSIL_SOURCE_DIR=<repo>/msil ...
```

On the Windows development host use `msil/utils/build/msil-configure.ps1`, which passes the
same two variables (see [utils/build/README.md](utils/build/README.md)). The MSIL target itself
is experimental: it goes in `LLVM_EXPERIMENTAL_TARGETS_TO_BUILD`, never in
`LLVM_TARGETS_TO_BUILD`. `MSIL.cmake` enables it once `llvm/lib/Target/MSIL` exists.

## Layout

| Path | Contents |
|---|---|
| `CMakeLists.txt` | the external project; adds `test/` when `LLVM_INCLUDE_TESTS` is on |
| `cmake/caches/MSIL.cmake` | CMake cache for CI: Release + assertions, clang and lld (`msil-ld` is lld's `msil` flavor), X86, experimental MSIL, this project |
| `.gitattributes` | LF line endings for everything here (expected transcripts are compared byte for byte) |
| `test/` | lit execution tests (`check-msil-exec`, per-directory `check-msil-*`, and `check-msil`, which also runs the MSIL lit tests outside `msil/`, `lld/test/MSIL`, the clang driver tests, the tests of `llvm-cil-dump` and `llvm-cil-copy` in `llvm/test/tools` and, since M18, the MC tests of `llvm/test/MC/MSIL` among them): `harness/` self-tests (`harness/prog/` for the multi-file composites, `dep-local.test` and `dep-wsl.test` for `--dep`, `il-snapshot.test` for the comparison of `utils/il-snapshot.py`, `canon-listing.test` for the canonical listing of `%msil_canon`, M16, which is `llvm-cil-dump --canonical` from M17, and `canon-agree.test`, M17, for its agreement with `mdcanon`), `M1/` milestone-1 programs (`M1/11-programs/` is the Design.md section 12 corpus), `M2/` programs of several files, archives and stock-clang bitcode that `msil-ld` links (M14), programs that call native libraries (`M2/03-native/`, M15), the link-semantics matrix (`M2/08-semantics/`) and the optional compile-only hosted tests (`M2/09-hosted/`, M15); `lit.cfg.py`'s `msil_pipeline` parameter builds the one-file C tests with `clang -S` (`asm`) or through `msil-ld` (`lto`), and the feature `msil-prog-pipeline=<p>` names the pipeline that `%{msil_prog}` uses, which guards checks that depend on it; the placeholders `%{msil_native_libs}` and `%{msil_deps}` give a test's native libraries to both builds and ship run-time files with the program, and `%{msil_ldflags}` links Linux triples with `--sysroot` (M15); see `test/README.md` |
| `utils/msil-run.py`, `utils/msil-verify.py`, `utils/ilverify-allowed.txt`, `utils/update-expected.py` | run a test program with a timeout and memory cap and compare its transcript (also a native Linux program inside WSL, `--native --runner wsl`); ILVerify/PEVerify with an allow-list (the verification policy, plan D21); regenerate or check expected transcripts from a native build (`--os linux`: the E7 Linux oracle and `<stem>.linux.expected`; the `%{msil_prog}` tests of `test/M2` through `msil-prog.py --mode native`, after the RUN lines that build a test's own native library). Since M15 `msil-run.py`, `msil-verify.py` and `msil-jitall.py` take `--dep FILE... --` (and `msil-run.py` `--dep-dir DIR`): the managed assemblies and native libraries a program needs, copied next to it (ILVerify references for the managed ones), also into WSL |
| `utils/msil-prog.py` | the build step of `%{msil_prog}` (M14): compiles each source with `clang -flto -c` (stock-clang sources for the native triple), builds the archives with `llvm-ar`, links through clang and `msil-ld` with `-Wl,--lto-emit-asm` and assembles the text with `ilasm -exe`; `--mode native` builds the same program natively (the oracle, also the E7 recipe, which links with `-rpath $ORIGIN` since M15), and `--det` builds it twice and compares the objects, archives and text; `--native-lib=ARGS` (M15) adds native link arguments to both modes; `--help` documents every option |
| `utils/linux-oracle/` | `start.c`, the minimal `_start` of the E7 Linux native oracle: it runs the program's `.init_array` constructors, then `exit(main(argc, argv))`, so a native Linux build links on Windows with `ld.lld` and no C library start files |
| `utils/make-linux-sysroot.py` | copies `libc.so.6`, `libm.so.6`, `libgcc_s.so.1` and the dynamic loader out of the WSL distribution into a sysroot outside the repository (default `$MSIL_LINUX_SYSROOT`, else `C:\llvm-msil-scratch\linux-sysroot`), with the linker scripts `libc.so` and `libm.so`, for the E7 oracle and, since M15, as `msil-ld`'s `--sysroot` for Linux-triple links; idempotent |
| `utils/make-glibc-sysroot.sh` | M15, run inside WSL or on any Debian-based Linux: `bash msil/utils/make-glibc-sysroot.sh DIR` builds a glibc sysroot with headers (`apt-get download` of `libc6-dev`, `linux-libc-dev`, `libc6` and `libgcc-s1`, unpacked with `dpkg-deb -x`, links copied as files) for the optional hosted tests (`test/M2/09-hosted`, lit's `msil_glibc_sysroot`); no root, idempotent, downloads only missing packages (`$MSIL_GLIBC_DEBS`, else `$HOME/.cache/msil/glibc-debs`) |
| `utils/il-snapshot.py` | M15: compiles every C and IR input that `HEAD` tracks under the given paths with `clang -S` and llc on four triples and keeps the IL and diagnostics (`--out DIR`); `--compare DIR` lists every difference from an earlier snapshot and exits 1, the proof that a change leaves `-S` and llc output byte-identical (D14 frozen; `llvm/docs/MSIL/GettingStarted.md` section 7); `test/harness/il-snapshot.test` pins that comparison on fixture trees. M18 added `--normalize forms`, which compares the `.il` files after mapping its shortest forms and `nomangle` back to Phase 1's (`normalize_forms()`) |
| `utils/check-il-forms-diff.py` | M18: reads `git diff -U0 <rev>` of the FileCheck tests under the given paths and accepts only mechanical changes: removed and added lines that are equal after `il-snapshot.py`'s `--normalize forms` (also applied, in escaped spelling, inside FileCheck's `{{...}}` regular expressions: the `ldc\.i4` forms, a `.s` or `\.s` suffix after a branch mnemonic or after a group of branch mnemonics only, and an optional `(\.s)?` group; labels, `[[...]]` variables and other mnemonics are left alone), RUN and DEFINE lines that only lose `--implicit-check-not=<pattern>` arguments naming a short form or `nomangle` (a lone argument on the last continuation line may go with its line), comment prose (not the comment lines that a RUN or DEFINE line runs as a program, such as `llvm/test/CodeGen/MSIL/switch.ll`'s `;PY ` lines: those pair with lines that are equal after `--normalize forms`, extended to quoted branch mnemonics, unless they hold a comment of the program's language), and removed `CHECK-NOT` lines that name a short form or `nomangle`; any other hunk, or an added or deleted file, fails. `--self-test` checks every rule in a temporary git repository; standard library only |
| `utils/msil-wsl-dotnet.sh` | run inside WSL: installs the private .NET runtimes 8.0.31 and 10.0.13 of the WSL test legs into `$HOME/.dotnet-msil` with Microsoft's `dotnet-install.sh` (no root, no system setting; `--print-path` prints the dotnet host) |
| `utils/jitall/`, `utils/msil-jitall.py` | force-JIT every method of an assembly without running it |
| `utils/mdtools/` | M16: the C# metadata oracles over System.Reflection.Metadata, which check the ECMA-335 library (`llvm/lib/CLI`) and what is built with it from outside. `mdcanon.cs` prints canonical listing v1 (plan 5.7.10), the layout-independent text of an assembly's metadata and IL, with the six normalization options of plan 5.12.6, `--order=decl`, `--forms=canon`, `--scopes=strip` and `--out-dir` batch mode; it was lit's `%msil_canon` in M16, and from M17 it is the second, independent implementation of the listing that `llvm-cil-dump --canonical` (lit's `%msil_canon` since M17) must match byte for byte. `mdump.cs` prints a raw listing for people, the `System.Reflection.Emit` opcode table (`--opcodes`) and a content ID (`--contentid`). `build-mdtools.py` compiles both offline, as `build-jitall.py` compiles jitall, into `<build>/tools/msil/mdtools` (lit runs it on configuration); `check-cil-defs.py` compares `llvm/include/llvm/BinaryFormat/CILOpcodes.def` with `mdump --opcodes`; `cli-corpus-check.py --mode ilasm` assembles every `clang -S` output of a test directory with the Framework and the NuGet ilasm and requires equal listings, and its M17 modes check the library's tools on the same programs: `dumpers` (`llvm-cil-dump --canonical` equals `mdcanon` on every image and its copy, with the default options and with every normalization), `copy` (`llvm-cil-copy`'s copies list like their images, are deterministic, and the copies of `test/M1/11-programs` verify, are force-JIT-compiled by `msil-jitall.py` (`--jitall DIR`) and run on .NET 8, five of them also on .NET 10, .NET Framework 4.8 and WSL) and `stats` (both dumpers' `--stats-only` on framework assemblies, and their `--canonical` listings of the same files and of the .NET 8 reference pack's `System.Runtime.dll`); M18's `encoder` mode (`--llc`, `--min-methods`) compares the bytes that `llc -show-mc-encoding` prints for every method of the programs with the Framework ilasm's image of the same text (code bytes, the token at each fixup, `.maxstack`); later milestones add modes |
| `utils/tools/msil-tools.proj` | NuGet download of ilasm/ildasm for Linux CI |
| `utils/build/` | PowerShell build, lit, syntax-check and TableGen helpers with the shared build lock (`msil-build.ps1 -Standard` builds the targets of `utils/ci/build-targets.txt`) |
| `utils/ci/` | the CI job steps as `.ps1`/`.sh` scripts that `.github/workflows/msil-ci.yml` and the local gate both call: configure, build (the targets of `build-targets.txt`, the one build-target list of the gates and CI, plan 5.6.11; `yaml2obj` and `llvm-mc` since M15, `llvm-cil-dump` and `llvm-cil-copy` since M17), unit tests (`CLITests` among them) and lit legs (each lit leg passes its arguments through a response file, `build/lit-results/<leg>.params.rsp`; since M14 the `lto` and `det` legs link through `msil-ld`; the optional `hosted` leg of M15 runs `test/M2/09-hosted` with the glibc sysroot, only when named; the `net8` leg runs `llvm/test/MC/MSIL` since M18, and the non-lit `encoder-parity` leg of M18, Windows only, runs `cli-corpus-check.py --mode encoder` over `test/M1`), plus the upstream-hooks check (`upstream-hooks.ps1`, Windows only, with `check-upstream-hooks.py`, which checks the manifest and judges the lit results) and the action-pin check (`check-action-pins.py`: the `msil-*.yml` workflows pin every action as upstream's workflows do) |
| `utils/run-m1-gate.ps1` | the milestone-1 gate: runs every leg (the `utils/ci/` scripts in CI order, the upstream-hooks check included, after a `host-setup` step that runs `msil-wsl-dotnet.sh`, `make-linux-sysroot.py` and `make-glibc-sysroot.sh` for the WSL legs, the last for the `hosted` leg) and prints one summary row per leg |
| `utils/upstream-hooks.txt` | the manifest of hooked upstream files: every upstream file the fork changes, with the upstream lit tests, unit tests or compile coverage that exercise the change and the fork tests that pin the MSIL side; upstream merges keep it complete (`llvm/docs/MSIL/GettingStarted.md` section 7) |
| `utils/run-utc-tests.py` | runs `update_llc_test_checks.py` tests (`msil-basic`, ...) without lit, which skips them on Windows; the `utc` leg of the gate and CI runs six of them |
| `utils/plan-check.py` | ownership, inputs and commit-scope checks of `llvm/docs/MSIL/ImplementationPlan.md` |

How to build the compiler, compile and run a C program, link a program of several files and
its native libraries with `msil-ld`, and run the tests:
[llvm/docs/MSIL/GettingStarted.md](../llvm/docs/MSIL/GettingStarted.md) (section 3 covers
`msil-ld`, native libraries and the instruction encodings of `llc -show-mc-encoding`, section 7
the tests, the native oracles, the WSL host setup, the IL snapshot, `check-il-forms-diff.py`
and the metadata oracles of `utils/mdtools/`; section 6 the ECMA-335 tools `llvm-cil-dump` and
`llvm-cil-copy`). What works so far,
the verification policy and the known runtime differences:
[llvm/docs/MSIL/Status.md](../llvm/docs/MSIL/Status.md). The design is in
[llvm/docs/MSIL/Design.md](../llvm/docs/MSIL/Design.md) and the implementation plan in
[llvm/docs/MSIL/ImplementationPlan.md](../llvm/docs/MSIL/ImplementationPlan.md).
