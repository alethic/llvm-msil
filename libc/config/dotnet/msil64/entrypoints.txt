# Entry points of LLVM libc on msil64-unknown-dotnet.
#
# P-1b ships the freestanding entry points only: no listed entry point, and no
# support object it pulls in, references the heap, atomics, the exit path, a
# clock, a File stream, the environment, signal names or the hash-table global
# (contract 5.19.4 of llvm/docs/MSIL/ImplementationPlan.md; the closure was
# measured on this tree). An OS-dependent function is absent, never a stub: the
# generated headers do not declare it, so a use is an undeclared-function error,
# or a link error naming c.dll through a program's own prototype. Every candidate
# that is not listed is named in a comment at the end, with its reason.
#
# Everything, math included, is in TARGET_LIBC_ENTRYPOINTS, so the one archive
# libc.a holds every object of c.dll (c.dll and libc.a are the same objects);
# TARGET_LIBM_ENTRYPOINTS stays empty, and the empty libm.a of the sysroot comes
# from msil/utils/build/build-libc.py. libc.src.errno.errno defines libc_errno,
# which the errno-setting entry points use; the errno cell is
# __llvm_libc_errno in src/__support/OSUtil/dotnet (LIBC_ERRNO_MODE_EXTERNAL).

# libc's CMake loads config/dotnet/config.json only when it derives the
# configuration directory from the triple. A LIBC_CONFIG_PATH naming
# config/dotnet/msil64 would skip that file silently and build with the default
# errno and thread modes, so this list refuses such a configuration.
if(NOT LIBC_CONF_ERRNO_MODE STREQUAL "LIBC_ERRNO_MODE_EXTERNAL" OR
   NOT LIBC_CONF_THREAD_MODE STREQUAL "LIBC_THREAD_MODE_SINGLE")
  message(FATAL_ERROR
    "libc build: config/dotnet/config.json was not applied "
    "(LIBC_CONF_ERRNO_MODE=${LIBC_CONF_ERRNO_MODE}, "
    "LIBC_CONF_THREAD_MODE=${LIBC_CONF_THREAD_MODE}); leave LIBC_CONFIG_PATH "
    "unset for msil64-unknown-dotnet and do not override these options.")
endif()

# setjmp.h declares setjmp, longjmp, sigsetjmp and siglongjmp, and nothing
# defines them: on MSIL triples the compiler intercepts calls to these
# declarations (contract 5.19.6). They are entry point names for the header
# generator only: they are not in TARGET_LIBC_ENTRYPOINTS, so no archive and no
# export list contains them. libc's CMake warns that the aliasees of
# libc.src.setjmp.setjmp and libc.src.setjmp.longjmp are missing, as expected.
set(TARGET_LLVMLIBC_ENTRYPOINTS
    ${TARGET_LIBC_ENTRYPOINTS}
    libc.src.setjmp.longjmp
    libc.src.setjmp.setjmp
    libc.src.setjmp.siglongjmp
    libc.src.setjmp.sigsetjmp
)

# Candidates that are not shipped, with the reason:
# math.h
#   acosh: no generic implementation upstream (src/math/generic)
#   asinh: no generic implementation upstream (src/math/generic)
#   atanh: no generic implementation upstream (src/math/generic)
#   copysignf80: its parameters and result are the emulated x87
#     struct fputil::Float80 (16 bytes, 16-aligned, SRET and byval in c.dll),
#     which matches no C type on msil64 (long double is binary64); no
#     installed header declares it (math.yaml has no entry), and 5.19.4
#     and the RuntimeLibcalls contract want no f80 surface
#   erf: no generic implementation upstream (src/math/generic)
#   fabsf80: its parameter and result are the emulated x87
